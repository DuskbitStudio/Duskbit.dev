## 2. 当前 LOGO：从大量探索收敛到 [ ■ ]

### 2.1 已定视觉语法

- 左边和右边各有一个直角中括号形面，中心为一个实心橙色正方形；左右整体对称，二维扁平。
- 左右括号采用深色/浅色前景色；中心方点固定橙色 `#F26B3A`。
- 不用渐变、拟物高光、不规则随机形状、复杂 3D 体块。
- 不要为了动画任意修改静态 Logo 的真实外形，不用蒙版去冒充原始标志笔画。**这里指 Logo 本身的几何真实性，不妨碍官网转场使用真正的页面遮罩。**
- 原始参考见 `source_assets/duskbit-logo-construction.html`（可调圆模数、辅助作图、标志纯净预览）和 `source_assets/duskbit-personal-swiss.html`（最新网页使用的 SVG symbol）。
- 交付包另外从最新 HTML **原样提取轮廓**得到 `derived_reference/duskbit-logo-light-transparent.svg` 与 `duskbit-logo-dark-transparent.svg`（无底色）。这只是便于 CC 使用的静态抽取文件。

### 2.2 最新 HTML 中的实际 SVG 数据

```svg
<symbol id="mark" viewBox="0 0 9.5 7">
  <path fill="currentColor" d="M0 0H2.5V1H1V6H2.5V7H0Z M9.5 0H7V1H8.5V6H7V7H9.5Z" />
  <rect x="3.25" y="2" width="3" height="3" fill="#F26B3A" />
</symbol>
```

- 基础单位 `u`；笔画厚度 `t = 1u`，bit 方块边长 `s = 3u`，括号最近水平净距 `g = 0.75u`，上下留白 `v = 2u`。
- 整体外接盒宽 `W = 9.5u`、高 `H = 7u`；橙方点居中，`x=3.25..6.25`、`y=2..5`。
- 比例推导是视觉设计的建议模数系统，不是不可更改的数学物理法则；但不能在没有充分理由时把现行标志改回历史版本。
- 用户曾认为两边括号离中心太远、看着像阿里云；经过两次收紧，最终参考采用上述 `0.75u` 水平留白。
- 需考虑 16 / 24 / 32 / 64 px 小尺寸的清晰度；构造器包含这几档检验。

### 2.3 GitHub 头像存在的细微冲突

`source_assets/duskbit-github-org.png` 是从 SVG 渲染来的 **1024×1024、1:1** GitHub Org 头像，中心橙色准确。这个早期文件的背景像素为 `#FAF9F6`（偏暖米白），但用户后续**明确否决奶油/暖米白色调**。所以它可作 Logo 尺寸与排版参考，**不应把原 PNG 的底色视为当下官网规范**。官网参考色更接近中性 `#FAFAFA`；正式头像可后续重新导出中性色或透明底，取决于发布需求。

## 3. 官网信息架构与功能（已确定）

- **React SPA**，用户已明确要求这一实现方式。此前的实现描述为 React + TypeScript；具体 bundler/配置需以 CC 手中现有仓库为准，不可凭交接文档推断。
- 首版是**单主页**：开场视觉 → navbar → 主视觉 Hero → **产品/项目** → **关于工作室** → Footer。首页可以重新构成布局，不必照抄现成占位内容。
- 主导航只有 **“产品 / 关于”** 两个内容入口；可保留独立的品牌首页入口与深浅色切换控件，但**不新增「手记/博客」栏目**。
- 页面必须自然交代“Duskbit 前身为 Feedra（feedra.org）”，不应喧宾夺主。
- 支持**浅色 / 深色**，并优先跟随系统；用户切换后记忆选择是已有 HTML 原型的能力。不得只做暗色方案。
- 适配桌面与移动端；触控和键盘可用；尊重 `prefers-reduced-motion`。
- navbar 左侧有 Logo，且在开场收尾后自然入场；整个过程不能跳帧、重影、闪白、内容抢先漏出。
- 初次进入播放 Logo 开场，SPA 站内切换不应反复弹出；曾有页脚重播入口，是现行实现历史，不是不可改的内容要求。
- 目前具体产品卡片和产品介绍文案**没有定稿**。不要把设计原型里的 `Desktop application / Connected service` 当作真实产品名。

## 4. 动画：务必以最后一条要求为准

这里有**两个不同阶段**，不能混淆。

**阶段 A（先前已实现/已确认可工作，现为旧版参考）：**

- Logo 初始处于屏幕正中央。
- 两侧中括号向左右退场，中心橙色方点放大，最终铺满屏幕。
- 然后内容淡入，nav 左侧 Logo 入场。
- 非线性运动，整个开场 **1.5 秒内**；曾实现为约 **1.45 秒**，用户反馈“整体过渡和 nav 的出现动画都没问题”。
- 先前助手曾称 React + TS 工程构建和类型检查通过；**本交接包并未拿到那个 React 项目的真实文件**，不能保证现在的仓库仍是该状态。

**阶段 B（最后提出的更新要求，应覆盖旧的核心转场路径）：**

> **“做一个中间那个点作为原点，让两个中括号以一定的曲线速度旋转扩大，然后互相穿过，穿过之后出现的界面的以蒙版形式显示 html。”**

- **中心橙色方块是旋转和放大的视觉原点**。
- 两只中括号绕它按非线性的曲线速度**旋转并扩大**，发生**互相穿过/交错**，产生空间穿越感；不能只是沿 X 轴各自滑走。
- 穿过后的网页以**真实遮罩/裁切蒙版（mask / clip）**逐步被揭示，具体遮罩拓扑由 CC 设计并验证；不是单纯叠一层淡入。
- 用户认可之前的整体流畅度、navbar 出场，因此**继承节奏和收尾质量，重做中段的几何运动与 reveal 逻辑**。
- 目标仍建议保持在 **≤1.5s**（最新指令没有解除此前的上限），无多余回弹、非线性顺滑、考虑慢设备和 reduced-motion。
- **当前没有证据表明阶段 B 已实际在 React 中完成**，交给 CC 时必须让它先检查代码再判断。

另一条早期独立 Logo 研究 `duskbit-logo-construction.html` 中的“2 秒 · 入场”属于**标志本身的展示动效**（两括号错峰靠拢、中心点后续放大），**不是官网阶段 B 的当前开场规格**。

## 5. 视觉与审美：定下来的原则

**选择的基础方向：瑞士风 / International Typographic Style。** 用户已在四版原生 HTML 对比稿中选择该方向，随后又要求它“有自己的特征”，不是通用的 Swiss Style 套皮。外观应从视觉语言体现独立开发者对结构、规则、精度、克制和一点实验性/玩味的偏好；不应用标签式文案硬讲性格。

### 必须遵守

- **严格排除奶油色、暖米白、复古纸张色**。色彩基底以中性的黑 / 白 / 灰为主。
- **橙色 `#F26B3A` 是品牌点睛色**；不宜到处大面积使用、稀释视觉焦点。
- LOGO 保持扁平纯色，不使用渐变填充；网页背景、卡片也不应依赖泛滥的商业模板渐变。
- 讲究网格、留白、非对称版式的平衡、字体层级、微小的标签/坐标/裁切感。避免过量装饰线和无意义的工程术语堆砌。
- 强调**网页是作品**：有个体审美，有主次、细节和节奏；不能只是“标准 landing page + 几张空卡片”。
- 不以“本人内向/独特/理性/敏感”等字眼做自述式 Hero 文案。
